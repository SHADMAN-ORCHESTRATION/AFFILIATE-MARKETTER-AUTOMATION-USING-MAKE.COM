# AFFILIATE-MARKETTER CUM UNIVERSAL POSTING-AUTOMATION-USING-MAKE.COM
a Make.com automation scenario designed to automatically detect the newest scraped social media content and publish it across multiple platforms without manual work. The workflow acts like a small automated publishing engine. Once a scraper collects new posts, the system analyzes the results, extracts the correct media and caption, determines the media type, and then distributes the content to the correct platform such as Instagram or YouTube.

The process begins when an Apify actor finishes running. Apify triggers a webhook that immediately wakes the scenario. At that moment the system retrieves the dataset generated by the actor run. The dataset normally contains multiple posts scraped from the source account, each including metadata such as timestamps, captions, image URLs, and video URLs.

Since the dataset can contain several posts, the automation does not blindly process everything. Instead, it aggregates the incoming dataset items and passes them into an AI processing step using the Gemini model. The AI receives several posts and is instructed to analyze the timestamps carefully. It identifies which post is the newest based on the date and time, assuming Asia/Kolkata timezone when the timezone is not present.

Once the latest post is selected, the AI extracts two important pieces of information. The first is the caption text from the selected post. The caption must remain unchanged except that any usernames or mentions beginning with the @ symbol are removed or replaced to avoid referencing the original creator. The second piece of information extracted is the media URLs associated with that post.

The workflow contains strict rules for handling these URLs. Many scraping systems generate signed URLs that contain security hashes. Because modifying these URLs would break them, the automation treats them as immutable strings. This means the system never reformats them, never escapes characters like ampersands, and never attempts to “clean” the link. The URL is passed exactly as it appears in the dataset.

After the AI returns the selected caption and media URLs, the scenario uses a regular expression parser to scan the AI output and isolate all valid HTTP or HTTPS links. This step ensures the workflow only processes real media URLs while ignoring any unexpected text that might appear in the output.

Once the URLs are collected, the automation aggregates them again and then passes them to a router. The router decides how the post should be published depending on the number of URLs and the file type contained in those URLs.

If the post contains a video file such as MP4 or MOV, the workflow follows the video publishing route. In this path the video URL is extracted and sent to Cloudinary. Cloudinary stores the video and generates a stable hosted URL that can be reliably used by social media APIs. After the upload is completed, the system creates a new Instagram Reel using the Instagram Business API and publishes the video to the configured account.

After the Instagram publishing step, the same video is downloaded as a binary file so that it can be uploaded to YouTube. The YouTube module then publishes the video using the configured YouTube account. If the YouTube upload fails for any reason, the automation ignores the error so the rest of the scenario continues running.

If the post contains a single image rather than a video, the automation follows a different branch. The image URL is extracted and sent directly to the Instagram Business API where it is published as a standard photo post along with the cleaned caption.

When the system detects multiple image URLs, the workflow recognizes that the post should become a carousel. In this case the automation iterates through the list of image URLs and aggregates them into an array of media files. Instagram allows a maximum of ten images per carousel, so the workflow limits the array accordingly. Once the files are prepared, the Instagram carousel module creates a multi-image post containing all the selected images.

Throughout the scenario there are several safety mechanisms built into the workflow. Some modules contain error handlers that prevent the entire automation from stopping if a single publishing step fails. This allows the automation to remain stable even when APIs occasionally return temporary errors.

The overall result is a fully automated content pipeline. A scraper collects posts from a source account, the workflow identifies the newest content, extracts the caption and media, determines whether the post is a video, image, or carousel, and then publishes the content automatically to the correct platform.

For meme pages or automated content distribution accounts, this kind of automation removes the need for manual reposting. Instead of constantly downloading posts and uploading them again to multiple platforms, the workflow handles the entire process in the background.

Because the scenario is built inside Make.com, it can easily be extended with additional modules. New platforms, storage services, or moderation steps can be added without redesigning the entire system. The workflow serves as a practical example of how AI processing, web scraping, and social media APIs can be combined to create a fully automated publishing system.
